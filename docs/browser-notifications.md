# HTTPS 自签名证书

测试环境可以使用自签名 HTTPS。使用 Nginx Alpine 直接加载 `/opt/specboard/certs/server.crt` 和 `server.key`，证书包含 `IP:10.9.34.84` SAN。Nginx 监听 `3443` 并反向代理 API；这样避免部分 macOS LibreSSL 客户端与 Caddy `tls internal` 的握手兼容问题。

```text
https://10.9.34.84:3443
```

首次访问会出现证书警告。确认这是测试服务器后，在浏览器中继续访问并信任证书；信任完成后该站点属于安全上下文，浏览器通知按钮可以请求权限。

- Chrome：继续访问后，在地址栏证书信息中导出或安装 Caddy Local Authority 根证书。
- Firefox：按提示接受例外；Firefox 使用独立证书存储。
- Safari：将根证书加入钥匙串并设置为始终信任。

自签名证书只适合测试或内网。正式环境应使用受信任 CA 或企业内部 CA。HTTP `:3000` 入口继续保留，通知在该入口仍会显示不可用。

仅使用浏览器 Notification API。默认停用，用户点击“启用通知”后请求授权；再次点击可停用。拒绝权限、API 缺失、非安全上下文和构造通知失败均不阻断看板，不产生页面 Toast。应用页面必须保持打开；后台页面可能被浏览器节流，页面关闭后不保证提醒，不包含 Web Push。

当前测试地址 http://10.9.34.84:3000 通常不是安全上下文，因此显示“通知不可用”。HTTPS 或浏览器认可的 localhost 可测试权限。localhost 的 HTTP 可被视为安全上下文，不能简单以协议判断。

通知来源为已有刷新快照，仅观察每个泳道最新 Top 20 首屏任务；加载更多和打开历史详情不会扩大关注范围。详情打开时仍独立刷新全部四泳道的 Top 20。首次看到任务只建立基线，不补发历史提醒；分页外的任务不保证收到提醒。任务离开范围即移除基线，重新进入时不补发历史通知；仍在四泳道并集内的阶段移动保留基线。多标签通过 BroadcastChannel 和共享 localStorage 做尽力去重，不保证同时竞争时 exactly-once。

为避免锁屏显示任意任务描述，正文仅含任务短编号、阶段和状态；不读取描述、错误或凭据。事件去重使用任务 ID、阶段/版本、运行或状态更新时间及事件类型；最多保存 200 个 key，不存任务正文。内存基线最多 2000 个任务。新启用通知会清空内存基线。

通知点击聚焦窗口并导航到本站受控 task/stage 参数，沿用登录状态；未连接时先连接，不请求任务数据，未来阶段忽略。部署只更新前端文件，不迁移数据库或改变任务状态。回滚可恢复上一 API 镜像的 public 文件；本地 specboard.browserNotifications 和 specboard.browserNotificationKeys 无需删除。退出后停止状态观察，浏览器权限本身需在站点设置中撤销。

验收：单元测试覆盖显式授权、拒绝、异常、启停、首次基线、重复失败、等待原因、重复轮询、存储异常、跨标签消息、有界 key 和受控链接。真实 Chrome 页面使用 Notification stub 验证按钮点击一次请求权限、数据库状态变化产生一条通知、点击通知打开 Propose、未登录零任务请求、拒绝与非安全上下文静默降级、移动端无溢出。stub 验证不代表操作系统横幅必定显示，系统勿扰/浏览器权限仍决定最终显示。

最终范围验收：真实 Chrome 后台标签（document.hidden=true）观察到状态变化并创建一次通知 stub；详情打开时四泳道请求均为 limit=20。全量 48 项测试通过，无跳过；行覆盖率 93.80%、函数覆盖率 93.71%。未部署。
