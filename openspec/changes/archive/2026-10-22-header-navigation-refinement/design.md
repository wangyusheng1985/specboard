## Context

参见 `proposal.md` 了解动机。目前系统主页头部由 Brand、Subtitle 和 `<nav>` 区域组成。所有操作按钮（连接、通知、项目、LLM、文档、创建任务）直接并列在 `<nav>` 内部，缺乏清晰的信息架构和视觉轻重层次。尤其是辅助性的 API 文档和配置按钮与主要生产操作“创建任务”视觉权重接近，缺乏专业开发工具的操作节奏感。

## Goals / Non-Goals

**Goals:**
- **清晰的信息层级**：通过 Flexbox 结构与间距分组，形成“连接状态 / 辅助配置 / 核心操作”三段式明确节奏。
- **视觉符号体系一致**：所有导航控制项统一配备 14px~15px 的矢量 SVG 图标，杜绝纯文字导致的视觉单调或样式不一。
- **状态可视化感知**：工作空间连接控制项整合在线状态指示灯（在线翠绿，离线中性灰），连接状况一目了然。
- **绝对防折行**：所有控制项内部强制 `white-space: nowrap`，图标与文字保持严格的垂直居中与固定 42px 高度基准。

**Non-Goals:**
- 不将控制项隐藏在多级二级折叠下拉菜单中，保持高频研发入口的一击即达（One-click Access）。
- 不破坏原有的 DOM id 映射（`#connect`, `#browser-notifications`, `#projects`, `#llm-settings`, `#new-task`），确保现有 `app.js` 逻辑完全无缝兼容。

## Decisions

### 1. 结构化分组布局与视觉锚点
- **决策**：在 `<nav>` 中保持扁平灵活的 Flex 布局，通过样式分隔类（如 `.nav-group`, `.nav-divider`）将辅助性工具按钮与主要的 `.primary` 创建任务按钮进行微空间区隔，将视觉焦点自然引向右侧的“创建任务”。
- **备选方案**：将项目与 LLM 配置移到下拉菜单。放弃原因：当前平台总配置项仅 2 个，下拉菜单会增加点击步长，违背“克制低噪声”原则。

### 2. 统一图标度量标准与交互反馈
- **决策**：
  - 图标标准：统一采用 `viewBox="0 0 16 16"` 矢量 SVG，线宽 `1.8px`，几何尺寸固定为 `14px × 14px`；
  - 动态状态点：连接控制项内的指示点定义为 6px 圆点，连接成功时添加 `.connected` 类并播放极微弱的翠绿呼吸微光；
  - 悬停动效：API 文档外链小图标在悬停时平滑斜移 1px，主要按钮在悬停时平滑微抬。

### 3. 向后兼容现有事件绑定
- **决策**：保持现有的所有 button/a 的 id 与 dataset 契约。在 `app.js` 中更新 `#connect` 的文本设置时，采用结构化保留或 helper 函数（如 `updateConnectStatus(connected)`），确保图标与状态点不受纯文本替换的影响。

## Risks / Trade-offs

- **[Risk] 按钮数量增多导致中等屏幕下溢出**
  → **Mitigation**：在媒体查询中，平板视口（`<1100px`）通过缩减 padding（`padding: 8px 11px`）并隐藏非核心副标题，在手机视口（`<600px`）自适应换行，确保各按钮单行完整不折行。
