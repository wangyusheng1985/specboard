## Why

当前任务详情头部（Header）由于外层卡片包裹、大字号标题（16px+ / 1.55 行高）以及多层元信息垂直堆叠，占用了超过 160px 的纵向高度。这在笔记本电脑或 88vh 视口的底部大画布弹窗中占据了首屏 20%~25% 的可视面积，导致核心工作内容区（如澄清表单、方案产物、代码交付记录）被极度压缩挤压。

同时，任务标识（短编号）目前隐藏在标题微卡片的次要位置，难以辨识，且不支持一键点击复制，团队成员在协同沟通或跨端定位问题时无法便捷分享当前任务的访问链接。基于专业 UI/UX 紧凑型信息架构与人机交互规范，亟需重构任务详情头部空间并增加可分享任务 ID 芯片。

## What Changes

- **任务详情头部空间极致紧凑化（Compact Header Hierarchy）**：
  - 去除过厚卡片容器套壳与冗余的“任务目标”次级栏，改为扁平紧凑的顶部通栏布局（内边距从 22px 压缩为 14px~16px）；
  - 任务标题采用更精致紧凑的字体层级（字号调整为 14.5px~15px，600 字重，行高 1.45），默认最多展示 2 行（`-webkit-line-clamp: 2`），鼠标悬停提供原生 title 提示；
  - 整体头部纵向高度压缩至约 80px，为下方实际业务内容直接释放 80px~100px 以上的关键可视高度。
- **重新布局任务编号并支持一键点击复制分享（Click-to-Copy Shareable ID Chip）**：
  - 将任务编号作为紧随仓库芯片（Repo Chip）旁的交互式元数据芯片（`.task-id-chip`），形式为 `[#7673c2cb 📋]`；
  - 鼠标悬停呈现平滑 Hover 反馈与 `点击复制分享链接` 提示；
  - 点击时自动复制当前任务的完整直达链接（`https://host:port/?task=<id>&stage=<stage>`），且图标在 2 秒内无缝切换为绿色对勾 `✓ 已复制`，同时触发轻量 Toast 反馈。

## Capabilities

### Modified Capabilities
- `ui-interaction-and-feedback`: 优化任务详情弹窗头部空间利用率，提供高信息密度、精简字号与防遮挡两行截断排版，并为任务短 ID 提供一键复制分享链接与微动效反馈。

## Impact

- 前端模板结构：`public/index.html`（详情弹窗头部微调）
- 界面样式表：`public/style.css`（头部紧凑排版、文字两行截断、可交互 ID 芯片样式）
- 交互与剪贴板逻辑：`public/app.js`（短 ID 渲染、链接复制与内联反馈状态机）
- 兼容性：所有 API 契约保持完全兼容。
