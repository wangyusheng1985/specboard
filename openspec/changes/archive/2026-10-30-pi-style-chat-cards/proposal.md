## Why

当前会话模式将多次工具调用全部聚合折叠在单一的分组盒子中，且缺失对模型思考链与各工具实际执行输出结果（toolResult）的细粒度呈现，无法让用户清晰了解智能体完整的思维推演轨迹与逐步探查过程。为了提供类似 Pi Coding Agent 的专业透明交互体验，需要将消息流重构为按时间线独立展开的多类型卡片（思考卡片、独立工具调用与结果卡片、正式回复卡片），让每次工具执行的入参与真实结果一目了然。

## What Changes

- **解耦工具调用卡片（取消聚合打包）**：
  - 彻底废除将多个工具调用聚合为一个 `chat-card-tools` 折叠盒的旧逻辑。
  - 每一个工具调用（如 `read`、`web_search`、`ls`、`fetch_content`）均作为独立的卡片节点渲染在消息时间线对应位置。
- **展示完整的 LLM 工具入参与执行结果（Tool Call & Tool Result）**：
  - 工具卡片内部分层展示：顶层为工具名称、执行状态与关键目标（如搜索关键词、读取路径）；展开后展示模型发起的完整请求参数与工具返回的实际输出内容（如文件前 N 行内容、搜索返回的摘要列表、网页正文摘要等）。
- **时间线流式顺序组织（Pi Agent 交互模式）**：
  - 消息流严格按照智能体思考与执行的真实发生顺序依次交织呈现：用户提问 ➔ [思考过程（思维链）] ➔ [工具卡片 1：入参 + 执行结果] ➔ [思考/推理] ➔ [工具卡片 2：入参 + 执行结果] ➔ [最终回复卡片]。
- **增强思考卡片（Thinking Card）的思考内容展示**：
  - 提取并展示模型伴随输出的思考分析内容或推理总结，支持折叠/展开与优雅的代码/引用排版。

## Capabilities

### Modified Capabilities
- `chat-mode`: 更新会话消息流交互规范，要求工具调用与执行独立展开展示入参及输出结果，并与思考卡片、回复卡片形成按时序排列的 Pi Agent 风格交互体系。

## Impact

- **受影响的前端代码**：
  - `public/app.js`：重构 `renderChatMessages` 算法，从“聚合归类渲染”升级为“时序事件驱动渲染”，分别维护各 `toolCallId` 的工具执行与结果绑定。
  - `public/style.css`：为独立的单项工具调用卡片定制高内聚样式，包括入参区、结果区、状态指示器及展开代码盒。
- **服务端契约兼容**：
  - 服务端既有的 `tool_execution_start` 与 `tool_execution_end` 事件 payload 结构已完整包含 `toolCallId`、`toolName`、`params` 与 `result`，前端无需改动服务端 API，仅对现有事件流进行充分可视化。
