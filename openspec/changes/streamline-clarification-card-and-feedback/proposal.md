## Why

在任务详情弹窗中，原本将“澄清问答”与“补充信息输入表单”耦合在一个固定卡片中，并硬编码冠以“待你确认”大标题。当任务在 Explore 阶段完成，或历史提出的澄清问题早已由用户回答并被 Agent 消费完毕后，界面依然在首屏最显要位置常驻展示“待你确认”大卡片以及重复的“问答记录”，不仅白白吞噬了首屏超过 300px 的垂直空间，将真正关键的“阶段过程产物”（交互式原型、调研架构）和“阶段成果”完全挤出视口，更直接引发了用户“我已经回答过了且探索都完成了，界面到底还要我确认什么”的严重认知混淆。

遵循 AGENTS.md“克制低噪声（仅展示与当前操作直接相关的信息，无诊断时完全隐藏诊断卡片）”的人机交互原则，必须彻底解耦澄清问答卡片与补充信息表单，实现“有待答问题时才呈现待你确认，无待答问题时静默隐藏并将首屏让渡给核心成果”。

## What Changes

- **澄清卡片动态按需渲染与自动隐藏（Contextual Clarification Card）**：
  - 仅在当前阶段真正存在待回答的澄清批次（`status === 'pending'`）时，才在首屏高亮展开“待你确认”卡片供用户填写与提交；
  - 当无未决澄清（无待答批次、澄清已被消费、或未触发过澄清）时，**完全隐藏“待你确认”卡片**；
  - 历史已完成的问答记录作为决策证据沉淀至下方“阶段成果与交互记录”中，不再在首屏顶部反复罗列；
- **补充信息表单独立轻量化排版（Decoupled Interaction / Feedback Bar）**：
  - 将补充信息表单（`#message-form`）从“待你确认”卡片中彻底剥离，重构为独立的轻量卡片（“补充需求与反馈”），排布在成果区附近，不再顶着“待你确认”的误导性招牌；
- **首屏第一视觉焦点让渡给核心产物与交付成果**：
  - 当任务进入“探索完成 · 待推进”或其他正常状态时，首屏第一卡片直接呈现“阶段过程产物”（HTML 原型、Markdown 方案）或“阶段成果”，极大提升阅读流畅度与操作决策效率。

## Capabilities

### Modified Capabilities
- `ui-interaction-and-feedback`: 优化任务详情弹窗信息架构与展示策略，实现澄清卡片仅在真正待答时可见并在完成后自动隐藏，解耦消息发送表单，释放首屏空间展示阶段过程产物与成果。

## Impact

- 前端模板骨架：`public/index.html`（解耦澄清容器与补充信息表单）
- 界面样式表：`public/style.css`（补充信息轻量卡片样式）
- 交互渲染逻辑：`public/app.js`（`renderClarifications` 条件渲染与卡片隐藏状态机）
- 兼容性：所有 API 与数据库数据保持完全兼容。
